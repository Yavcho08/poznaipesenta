# Познай песента — план

Уеб игра „Познай песента“ с фокус върху българската поп-фолк музика.

## Стек
- Next.js 16 (App Router, `cacheComponents`) + TypeScript (strict) + Tailwind CSS 4
- Prisma 7 ORM; SQLite при разработка (`@prisma/adapter-better-sqlite3`), лесно преминаване към Postgres
- Vitest за unit тестове
- Без платени външни услуги

## Технически ограничения
1. **Spotify** — само източник на списък с песни, НИКОГА на звук. Не връща `preview_url` за нови приложения (от 11.2024). Development Mode: макс. 5 потребители (от 02.2026); `GET /playlists/{id}/items` — само за плейлисти на влезлия потребител; search limit 10.
2. **Звук от Deezer** (`api.deezer.com`, без ключ): 30-сек. preview MP3.
   - Preview URL-ите са подписани и изтичат след няколко часа → в базата пазим само `deezerId`; свеж URL от `GET /track/{id}` при старт на рунд.
   - Няма CORS → всичко минава през Next.js route handlers. Кеш на метаданните, rate limit ~50 заявки / 5 сек.
   - Песни без preview се пропускат.
3. **Резервен звук**: iTunes Search API (`country=BG`).
4. Не съхраняваме аудио файлове — само стрийм.

## Геймплей
- Стъпки на клипа: **0.2 / 1 / 2 / 5 / 10 сек**, всички от една и съща точка — **припева** в preview-то (най-силната част с ясно „влизане“; изчислява се на сървъра). *Променено по желание: от позиция 0 никой не познаваше.*
- Отговорът се избира от combobox („Заглавие – Артист“ с малка обложка). Без свободен текст, без 4 варианта.
- Вярно → край на рунда, точки по стъпка: **100 / 80 / 60 / 40 / 20**.
- Грешно или „Пропусни“ → следваща стъпка. Грешните опити се показват като списък над полето (като в Heardle).
- Грешка на 10-сек. стъпка → 0 точки, показва се верният отговор (обложка, заглавие, артист, пълен preview) + „Следваща песен“.
- Игра = 10 рунда, накрая екран с резултати по рундове. Бутон „Пусни пак“.

### Аудио
- Web Audio API (не `HTMLAudioElement` за таймингите). `/api/audio/[deezerId]` проксира MP3-то.
- Клиентът: fetch → `decodeAudioData` → `AudioBufferSourceNode.start(0, 0, duration)`; fade-out ~30 ms.
- Предварително зареждане на аудиото за следващия рунд.
- Първото пускане след клик (autoplay политики). Прогрес бар за дължината на клипа.

### Търсене (combobox)
- `/api/search?q=`, debounce 250 ms, мин. 2 символа.
- Търси в целия Deezer каталог + нашата база (за да не се издава отговорът).
- Съвпадение с артист (нормализирано име) → първо неговите песни по популярност (`/artist/{id}/top?limit=50`, сорт по `rank`), после останалите.
- Иначе — по `rank`.
- Кирилица и латиница: транслитерация (официалния български стандарт), търсене в двата варианта, обединяване.
- Без дубликати (нормализирани title + artist).
- Клавиатура (стрелки, Enter, Esc), работи на телефон.
- Проверка на отговора: нормализирани title + основен artist (lowercase, транслитерация, без „(feat. …)“, „- Remix“, „Live“, „Radio Edit“, пунктуация) — НЕ по `deezerId`. Unit тестове с реални български заглавия.

## Модел на данните
`Artist`, `Genre` (m:n с Artist), `Track`, `Playlist` (+ `PlaylistTrack` с позиция), `GameSession`, `Round` (`solvedAtStep`, `guesses` Json), `Score`. Виж `prisma/schema.prisma`.

## Решения, взети по пътя
- **Мултиплейър транспорт:** нито Supabase, нито Socket.io — кратко питане (1 сек.) + обща времева линия от сървърното време (`src/lib/room/timeline.ts`). Синхронът на звука идва от насрочено пускане в Web Audio, не от скоростта на съобщенията. Работи на Vercel без външна услуга; транспортът може да се смени със Supabase Realtime без промяна на логиката.
- **Проверка на отговор при дуети:** заглавието съвпада + основният артист на едната версия участва в другата (иначе „Тази дискотека“ на Galin ≠ същата песен, водена на Azis).
- **Разпознаване на артист:** освен точно име и водещи фенове, профилът трябва да е „български“ (кирилица/познати артисти в top песните) — иначе „Andrea“/„Emilia“ биха хванали чужди артисти.
- **Плейлисти по десетилетия:** по `release_date` от Deezer, който често е датата на компилация/преиздаване → „Нов поп-фолк“ е прекалено голям. Курира се ръчно в `/admin`.
